# ГЭ 12. Базы данных: подробный ответ

Расширенная версия по реляционной алгебре, целостности, SQL и нормальным формам.

---

## 1. Реляционная модель

Реляционная модель представляет данные в виде отношений.

Термины:

| Термин | Практический аналог |
|---|---|
| Отношение | таблица |
| Кортеж | строка |
| Атрибут | столбец |
| Домен | множество допустимых значений |
| Первичный ключ | идентификатор строки |
| Внешний ключ | ссылка на другую таблицу |

Важное свойство: строки в отношении не имеют фиксированного порядка, а дубликаты в строгой реляционной модели не допускаются.

---

## 2. Реляционная алгебра

Реляционная алгебра - формальный язык операций над отношениями. Результат каждой операции снова является отношением.

Основные операции:

- выборка;
- проекция;
- переименование;
- объединение;
- пересечение;
- разность;
- декартово произведение;
- естественное соединение.

### Выборка

Выборка оставляет строки по условию.

```text
sigma_condition(R)
```

SQL:

```sql
SELECT *
FROM R
WHERE condition;
```

### Проекция

Проекция оставляет указанные столбцы.

```text
pi_columns(R)
```

SQL:

```sql
SELECT DISTINCT column1, column2
FROM R;
```

### Переименование

Переименование нужно для изменения имен и устранения неоднозначности.

```sql
SELECT name AS student_name
FROM Students AS s;
```

### Объединение, пересечение, разность

Эти операции требуют совместимости отношений: одинакового числа атрибутов и совместимых доменов.

SQL:

```sql
SELECT * FROM A
UNION
SELECT * FROM B;
```

```sql
SELECT * FROM A
INTERSECT
SELECT * FROM B;
```

```sql
SELECT * FROM A
EXCEPT
SELECT * FROM B;
```

### Декартово произведение и соединение

Декартово произведение соединяет каждую строку первой таблицы с каждой строкой второй.

Соединение фактически является произведением плюс условием отбора.

```sql
SELECT *
FROM Orders
JOIN Customers ON Orders.customer_id = Customers.id;
```

Естественное соединение выполняется по одноименным атрибутам, но в SQL его часто избегают, потому что оно зависит от совпадения имен столбцов.

## 3. Целостность данных

Целостность - корректность и непротиворечивость данных.

Уровни ограничений:

### Уровень атрибута

Ограничение относится к одному столбцу.

Примеры:

- тип данных;
- `NOT NULL`;
- `CHECK`;
- значение по умолчанию.

### Уровень кортежа

Ограничение связывает поля одной строки.

```sql
CHECK (end_date >= start_date)
```

### Уровень отношения

Ограничение относится к таблице:

- первичный ключ;
- уникальность;
- ограничения на множество строк.

### Уровень базы данных

Ограничения между таблицами, прежде всего внешние ключи.

---

## 4. Ссылочная целостность

Внешний ключ должен ссылаться на существующую строку родительской таблицы или быть `NULL`, если это разрешено.

Пример:

```sql
CREATE TABLE Orders (
    id INT PRIMARY KEY,
    customer_id INT,
    FOREIGN KEY (customer_id) REFERENCES Customers(id)
);
```

Правила:

| Правило | Что делает |
|---|---|
| `RESTRICT` | запрещает удаление или изменение родителя |
| `NO ACTION` | не выполняет автоматического действия |
| `CASCADE` | переносит удаление или изменение на дочерние строки |
| `SET NULL` | ставит внешний ключ в `NULL` |
| `SET DEFAULT` | ставит значение по умолчанию |

## 5. SQL

SQL - декларативный язык реляционных баз данных.

Группы:

- DDL: `CREATE`, `ALTER`, `DROP`;
- DML: `INSERT`, `UPDATE`, `DELETE`;
- DQL: `SELECT`;
- DCL: `GRANT`, `REVOKE`;
- TCL: `COMMIT`, `ROLLBACK`.

Порядок логической обработки `SELECT`:

1. `FROM`;
2. `WHERE`;
3. `GROUP BY`;
4. `HAVING`;
5. `SELECT`;
6. `ORDER BY`.

Пример:

```sql
SELECT customer_id, COUNT(*) AS order_count
FROM Orders
WHERE status = 'paid'
GROUP BY customer_id
HAVING COUNT(*) > 3
ORDER BY order_count DESC;
```

## 6. Нормализация

Нормализация уменьшает избыточность и предотвращает аномалии.

Аномалии:

- вставки;
- обновления;
- удаления.

Функциональная зависимость:

```text
X -> Y
```

означает, что `X` однозначно определяет `Y`.

### 1НФ

Все значения атомарны. В одной ячейке не должно быть списков.

### 2НФ

Отношение в 1НФ, и каждый неключевой атрибут полностью зависит от всего составного ключа.

Нарушение:

```text
(student_id, course_id) -> grade
student_id -> student_name
```

### 3НФ

Отношение во 2НФ, и нет транзитивных зависимостей неключевых атрибутов от ключа.

Нарушение:

```text
student_id -> group_id
group_id -> group_name
```

## 7. Полный устный ответ

База данных в реляционной модели представляет данные в виде отношений. Реляционная алгебра задает формальные операции над отношениями: выборку, проекцию, переименование, объединение, пересечение, разность, декартово произведение и соединение. SQL реализует эти операции через `SELECT`, `WHERE`, список столбцов, `AS`, `UNION`, `INTERSECT`, `EXCEPT`, `JOIN`.

Целостность данных означает согласованность допустимых состояний базы. Ограничения бывают уровня атрибута, кортежа, отношения и базы данных. Ссылочная целостность поддерживается внешними ключами и правилами `RESTRICT`, `CASCADE`, `SET NULL`, `SET DEFAULT`, `NO ACTION`.

Нормализация приводит отношения к нормальным формам. 1НФ требует атомарности, 2НФ устраняет зависимости от части составного ключа, 3НФ устраняет транзитивные зависимости.
