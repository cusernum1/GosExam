## 2. Вопрос 1. Модульность. Критерии, правила, принципы

Этот вопрос пересекается с ООП, но в контексте баз данных его удобно рассматривать через проектирование приложений, работающих с данными, и через разбиение информационной системы на уровни.

### 2.1. Модульность в информационных системах

Информационная система обычно состоит из нескольких уровней:

- пользовательский интерфейс;
- бизнес-логика;
- слой доступа к данным;
- база данных;
- внешние интеграции.

Модульность означает, что каждый уровень и каждый компонент имеет свою ответственность и взаимодействует с другими через определенные интерфейсы.

### 2.2. Пример модульного разбиения

Пример приложения для учета заказов:

| Модуль | Ответственность |
|---|---|
| `CustomerService` | работа с клиентами |
| `OrderService` | оформление заказов |
| `PaymentService` | платежи |
| `OrderRepository` | доступ к таблице заказов |
| `CustomerRepository` | доступ к таблице клиентов |
| База данных | хранение и контроль целостности данных |

Такое разбиение позволяет отдельно изменять бизнес-логику, SQL-запросы и интерфейс пользователя.

### 2.3. Критерии модульности

Критерии:

- декомпозируемость;
- компонуемость;
- понятность;
- непрерывность;
- защищенность.

В системах баз данных особенно важны:

- разделение логики приложения и логики хранения;
- отсутствие дублирования SQL-запросов;
- централизованное описание ограничений;
- ясная схема данных;
- минимизация зависимостей между таблицами и программным кодом.

### 2.4. Правила и принципы

Основные правила:

1. Каждый модуль должен иметь одну ответственность.
2. Детали хранения данных должны быть скрыты за интерфейсом доступа.
3. SQL-запросы должны быть понятными и проверяемыми.
4. Бизнес-правила должны быть выражены либо в приложении, либо в ограничениях БД, но не хаотично продублированы.
5. Изменение структуры таблиц не должно требовать переписывания всей системы.

### 2.5. Экзаменационный ответ

Модульность в системах баз данных означает разбиение информационной системы на части с четкой ответственностью: пользовательский интерфейс, бизнес-логику, слой доступа к данным и собственно базу данных. Такая организация позволяет уменьшить сложность, локализовать изменения, повысить надежность и упростить сопровождение.

Критериями модульности являются декомпозируемость, компонуемость, понятность, непрерывность и защищенность. Важными принципами являются слабая связность, высокая внутренняя связность, скрытие деталей реализации и ясные интерфейсы между модулями.

## 3. Вопрос 2. ООП. Качество ПО. Внешние и внутренние факторы

### 3.1. Связь ООП и баз данных

Во многих информационных системах объектно-ориентированная модель приложения взаимодействует с реляционной моделью базы данных.

Классы приложения могут соответствовать сущностям предметной области:

- `Customer`;
- `Order`;
- `Product`;
- `Invoice`.

Таблицы базы данных хранят состояния этих сущностей.

### 3.2. Качество ПО в приложениях с базами данных

Качество такой системы зависит не только от кода, но и от схемы данных.

Внешние факторы качества:

- корректность работы запросов;
- надежность хранения данных;
- скорость выполнения операций;
- удобство использования;
- безопасность доступа;
- сохранность данных;
- согласованность результатов.

Внутренние факторы качества:

- нормализованная схема данных;
- понятные имена таблиц и атрибутов;
- отсутствие дублирования данных;
- корректные ключи и ограничения;
- читаемые SQL-запросы;
- разделение бизнес-логики и доступа к данным;
- тестируемость запросов;
- управляемость миграций схемы.

### 3.3. Пример влияния внутреннего качества на внешнее

Если в базе данных не заданы внешние ключи, приложение может позволить создать заказ для несуществующего клиента.

С точки зрения пользователя это проявится как ошибка работы системы.

С точки зрения внутреннего качества причина состоит в отсутствии ограничения ссылочной целостности.

### 3.4. Экзаменационный ответ

ООП помогает строить информационные системы через классы, объекты и интерфейсы, а база данных обеспечивает долговременное хранение состояния объектов. Качество ПО в таких системах определяется как кодом приложения, так и качеством схемы базы данных.

Внешние факторы качества включают корректность, надежность, производительность, безопасность и удобство использования. Внутренние факторы включают модульность, читаемость кода, нормализацию схемы, целостность данных, ясность SQL-запросов и сопровождаемость.

## 4. Вопрос 3. Язык SQL. Реализация операций реляционной алгебры

### 4.1. Назначение SQL

SQL - это декларативный язык для работы с реляционными базами данных.

SQL используется для:

- создания схемы базы данных;
- добавления данных;
- изменения данных;
- удаления данных;
- выборки данных;
- описания ограничений;
- управления правами доступа;
- управления транзакциями.

### 4.2. Основные группы операторов SQL

| Группа | Назначение | Примеры |
|---|---|---|
| DDL | определение структуры данных | `CREATE`, `ALTER`, `DROP` |
| DML | изменение данных | `INSERT`, `UPDATE`, `DELETE` |
| DQL | выборка данных | `SELECT` |
| DCL | управление правами | `GRANT`, `REVOKE` |
| TCL | управление транзакциями | `COMMIT`, `ROLLBACK` |

### 4.3. Общая форма SELECT

```sql
SELECT список_атрибутов
FROM список_таблиц
WHERE условие
GROUP BY атрибуты_группировки
HAVING условие_для_групп
ORDER BY порядок_сортировки;
```

### 4.4. Выборка в реляционной алгебре и SQL

Операция выборки оставляет только те строки, которые удовлетворяют условию.

Реляционная алгебра:

```text
sigma_{condition}(R)
```

SQL:

```sql
SELECT *
FROM Students
WHERE age > 18;
```

### 4.5. Проекция

Проекция оставляет только указанные атрибуты.

Реляционная алгебра:

```text
pi_{name, age}(Students)
```

SQL:

```sql
SELECT name, age
FROM Students;
```

Если нужно убрать дубликаты:

```sql
SELECT DISTINCT name, age
FROM Students;
```

### 4.6. Переименование

Переименование меняет имя отношения или атрибута.

SQL:

```sql
SELECT name AS student_name
FROM Students AS s;
```

### 4.7. Объединение

Операция объединения возвращает строки, принадлежащие хотя бы одному из отношений.

SQL:

```sql
SELECT id, name
FROM Students2025
UNION
SELECT id, name
FROM Students2026;
```

`UNION` удаляет дубликаты.

`UNION ALL` сохраняет дубликаты.

### 4.8. Пересечение

Операция пересечения возвращает строки, присутствующие в обоих отношениях.

SQL:

```sql
SELECT id
FROM GroupA
INTERSECT
SELECT id
FROM GroupB;
```

Если СУБД не поддерживает `INTERSECT`, можно использовать `INNER JOIN`.

### 4.9. Разность

Разность возвращает строки первого отношения, отсутствующие во втором.

SQL:

```sql
SELECT id
FROM GroupA
EXCEPT
SELECT id
FROM GroupB;
```

В некоторых СУБД используется `MINUS`.

### 4.10. Декартово произведение

Декартово произведение соединяет каждую строку первого отношения с каждой строкой второго.

SQL:

```sql
SELECT *
FROM Students
CROSS JOIN Courses;
```

Если в первой таблице `m` строк, а во второй `n` строк, результат содержит `m*n` строк.

### 4.11. Соединение

Соединение связывает строки разных таблиц по условию.

SQL:

```sql
SELECT Students.name, Groups.group_name
FROM Students
JOIN Groups ON Students.group_id = Groups.id;
```

Естественное соединение в реляционной алгебре соединяет отношения по одноименным атрибутам. В SQL есть `NATURAL JOIN`, но на практике его используют осторожно, потому что результат зависит от совпадения имен столбцов.

### 4.12. Экзаменационный ответ

SQL является декларативным языком работы с реляционными базами данных. Основной оператор выборки - `SELECT`. Операции реляционной алгебры реализуются в SQL следующим образом: выборка через `WHERE`, проекция через список столбцов в `SELECT`, переименование через `AS`, объединение через `UNION`, пересечение через `INTERSECT`, разность через `EXCEPT` или `MINUS`, декартово произведение через `CROSS JOIN`, соединение через `JOIN`.

## 5. Вопрос 4. Целостность в базах данных по состоянию

### 5.1. Понятие целостности данных

Целостность данных означает правильность, согласованность и непротиворечивость данных в базе.

Ограничения целостности задают правила, которым должны удовлетворять данные в каждый допустимый момент времени.

Целостность по состоянию означает, что каждое состояние базы данных должно удовлетворять заданным ограничениям.

### 5.2. Ограничения уровня атрибута

Ограничения уровня атрибута задаются для отдельного столбца.

Примеры:

- тип данных;
- `NOT NULL`;
- `CHECK`;
- значение по умолчанию;
- допустимый диапазон.

SQL:

```sql
CREATE TABLE Students (
    id INT PRIMARY KEY,
    age INT CHECK (age >= 16),
    name VARCHAR(100) NOT NULL
);
```

### 5.3. Ограничения уровня кортежа

Ограничения уровня кортежа задают условие для одной строки таблицы.

Пример:

```sql
CREATE TABLE Orders (
    id INT PRIMARY KEY,
    start_date DATE NOT NULL,
    end_date DATE NOT NULL,
    CHECK (end_date >= start_date)
);
```

Здесь ограничение проверяет соотношение двух атрибутов одной строки.

### 5.4. Ограничения уровня отношения

Ограничения уровня отношения относятся ко всей таблице.

К ним относятся:

- первичный ключ;
- уникальность;
- ограничения на множество строк.

Пример:

```sql
CREATE TABLE Students (
    id INT PRIMARY KEY,
    email VARCHAR(255) UNIQUE,
    name VARCHAR(100) NOT NULL
);
```

Первичный ключ обеспечивает уникальную идентификацию строк.

### 5.5. Ограничения уровня базы данных

Ограничения уровня базы данных связывают несколько таблиц.

Главный пример - внешний ключ.

```sql
CREATE TABLE Orders (
    id INT PRIMARY KEY,
    customer_id INT NOT NULL,
    FOREIGN KEY (customer_id) REFERENCES Customers(id)
);
```

Такое ограничение запрещает создать заказ для клиента, которого нет в таблице `Customers`.

### 5.6. Ссылочная целостность

Ссылочная целостность означает, что значение внешнего ключа должно либо ссылаться на существующую строку родительской таблицы, либо быть `NULL`, если это разрешено.

Например:

```text
Каждый заказ должен ссылаться на существующего клиента.
```

### 5.7. Правила поддержания ссылочной целостности

При удалении или изменении родительской строки возможны разные правила.

| Правило | Смысл |
|---|---|
| `RESTRICT` | запретить изменение или удаление, если есть зависимые строки |
| `NO ACTION` | аналогично запрету, проверка может быть отложенной |
| `CASCADE` | автоматически изменить или удалить зависимые строки |
| `SET NULL` | установить внешний ключ в `NULL` |
| `SET DEFAULT` | установить значение по умолчанию |

Пример:

```sql
CREATE TABLE Orders (
    id INT PRIMARY KEY,
    customer_id INT,
    FOREIGN KEY (customer_id)
        REFERENCES Customers(id)
        ON DELETE SET NULL
        ON UPDATE CASCADE
);
```

### 5.8. Экзаменационный ответ

Целостность данных означает согласованность и допустимость данных в базе. Целостность по состоянию требует, чтобы каждое состояние базы данных удовлетворяло заданным ограничениям.

Ограничения могут задаваться на уровне атрибута, кортежа, отношения и всей базы данных. На уровне атрибута задаются типы, `NOT NULL`, `CHECK`. На уровне кортежа задаются условия между полями одной строки. На уровне отношения задаются первичные ключи и уникальность. На уровне базы данных задаются связи между таблицами, прежде всего внешние ключи.

Ссылочная целостность требует, чтобы внешний ключ ссылался на существующую строку родительской таблицы. Для поддержания ссылочной целостности используются правила `RESTRICT`, `CASCADE`, `SET NULL`, `SET DEFAULT`, `NO ACTION`.

## 6. Вопрос 5. Реляционная алгебра

### 6.1. Понятие реляционной алгебры

Реляционная алгебра - это формальная система операций над отношениями.

Отношение можно понимать как таблицу, состоящую из строк и столбцов.

Операции реляционной алгебры принимают одно или несколько отношений и возвращают новое отношение.

Это важно: результат операции снова является отношением, поэтому операции можно комбинировать.

### 6.2. Выборка

Выборка отбирает кортежи, удовлетворяющие условию.

```text
sigma_condition(R)
```

Свойства:

- не меняет набор атрибутов;
- уменьшает или сохраняет число строк;
- может быть объединена с другой выборкой.

Пример:

```text
выбрать студентов старше 18 лет
```

### 6.3. Проекция

Проекция выбирает указанные атрибуты.

```text
pi_attributes(R)
```

Свойства:

- уменьшает или сохраняет число столбцов;
- в классической реляционной алгебре удаляет дубликаты;
- может уменьшить число строк из-за удаления дубликатов.

### 6.4. Переименование

Переименование изменяет имена отношения или атрибутов.

Оно нужно:

- для устранения неоднозначности;
- для подготовки к соединению;
- для самосоединения отношения с самим собой.

### 6.5. Объединение

Объединение:

```text
R union S
```

возвращает кортежи, которые принадлежат `R` или `S`.

Условие применимости:

```text
отношения должны быть совместимы по объединению
```

То есть они должны иметь одинаковое число атрибутов и совместимые домены.

Свойства:

- коммутативность;
- ассоциативность;
- идемпотентность.

### 6.6. Пересечение

Пересечение:

```text
R intersect S
```

возвращает кортежи, которые принадлежат одновременно `R` и `S`.

Свойства:

- коммутативность;
- ассоциативность;
- идемпотентность.

### 6.7. Разность

Разность:

```text
R minus S
```

возвращает кортежи, которые принадлежат `R`, но не принадлежат `S`.

Разность не является коммутативной.

Обычно:

```text
R minus S не равно S minus R
```

### 6.8. Декартово произведение

Декартово произведение:

```text
R times S
```

соединяет каждый кортеж `R` с каждым кортежем `S`.

Если в `R` содержится `m` строк, а в `S` содержится `n` строк, результат содержит `m*n` строк.

Декартово произведение часто используется как основа для соединений.

### 6.9. Естественное соединение

Естественное соединение объединяет отношения по одноименным атрибутам.

Идея:

```text
соединить строки, у которых совпадают значения общих атрибутов
```

После соединения одинаковые атрибуты не дублируются.

### 6.10. Свойства операций

Основные свойства:

| Операция | Важные свойства |
|---|---|
| Выборка | может распределяться по объединению |
| Проекция | может удалять дубликаты |
| Объединение | коммутативно и ассоциативно |
| Пересечение | коммутативно и ассоциативно |
| Разность | некоммутативна |
| Декартово произведение | размер результата равен произведению размеров |
| Соединение | часто выражается через произведение и выборку |

Соединение через произведение и выборку:

```text
R join_condition S = sigma_condition(R times S)
```

### 6.11. Экзаменационный ответ

Реляционная алгебра - это формальная система операций над отношениями. Основными операциями являются выборка, проекция, переименование, объединение, пересечение, разность, декартово произведение и естественное соединение.

Выборка отбирает строки по условию, проекция выбирает столбцы, переименование меняет имена, объединение возвращает кортежи из двух отношений, пересечение - общие кортежи, разность - кортежи первого отношения, отсутствующие во втором, декартово произведение соединяет каждую строку одного отношения с каждой строкой другого, а естественное соединение связывает отношения по общим атрибутам.

## 7. Вопрос 6. Нормальные формы реляционных баз данных

### 7.1. Понятие нормализации

Нормализация - это процесс организации структуры реляционной базы данных с целью уменьшения избыточности и устранения аномалий изменения данных.

Аномалии бывают:

- аномалия вставки;
- аномалия обновления;
- аномалия удаления.

### 7.2. Функциональная зависимость

Функциональная зависимость означает, что значение одного набора атрибутов однозначно определяет значение другого набора атрибутов.

Запись:

```text
X -> Y
```

означает:

```text
если две строки имеют одинаковые значения X, то они имеют одинаковые значения Y
```

Пример:

```text
student_id -> student_name
```

Идентификатор студента определяет имя студента.

### 7.3. Ключ

Ключ - это набор атрибутов, который однозначно идентифицирует кортеж отношения.

Виды ключей:

- потенциальный ключ;
- первичный ключ;
- внешний ключ;
- составной ключ.

### 7.4. Первая нормальная форма

Отношение находится в первой нормальной форме, если все значения атрибутов атомарны.

Это означает, что в одной ячейке не должно быть списка значений.

Нарушение 1НФ:

| student_id | phones |
|---|---|
| 1 | `+7-111, +7-222` |

Приведение к 1НФ:

| student_id | phone |
|---|---|
| 1 | `+7-111` |
| 1 | `+7-222` |

### 7.5. Вторая нормальная форма

Отношение находится во второй нормальной форме, если:

1. оно находится в первой нормальной форме;
2. каждый неключевой атрибут полностью функционально зависит от всего составного ключа, а не от его части.

2НФ важна для таблиц с составным ключом.

Пример нарушения:

| student_id | course_id | student_name | grade |
|---|---|---|---|
| 1 | 10 | Иванов | 5 |

Ключ:

```text
(student_id, course_id)
```

Но:

```text
student_id -> student_name
```

Значит `student_name` зависит только от части ключа. Это нарушение 2НФ.

Исправление:

```text
Students(student_id, student_name)
Grades(student_id, course_id, grade)
```

### 7.6. Третья нормальная форма

Отношение находится в третьей нормальной форме, если:

1. оно находится во второй нормальной форме;
2. нет транзитивных зависимостей неключевых атрибутов от ключа.

Пример нарушения:

| student_id | group_id | group_name |
|---|---|---|
| 1 | 101 | МКН-1 |

Зависимости:

```text
student_id -> group_id
group_id -> group_name
```

Следовательно:

```text
student_id -> group_name
```

через `group_id`. Это транзитивная зависимость.

Исправление:

```text
Students(student_id, group_id)
Groups(group_id, group_name)
```

### 7.7. Зачем нужны нормальные формы

Нормализация позволяет:

- уменьшить дублирование данных;
- избежать противоречивых обновлений;
- упростить поддержку целостности;
- сделать структуру базы логически ясной;
- уменьшить риск аномалий вставки и удаления.

Но чрезмерная нормализация может усложнить запросы и снизить производительность. Поэтому в практических системах иногда применяют денормализацию, если это осознанно нужно для ускорения чтения.

### 7.8. Экзаменационный ответ

Нормализация - это процесс приведения отношений базы данных к нормальным формам для уменьшения избыточности и устранения аномалий вставки, обновления и удаления.

Первая нормальная форма требует атомарности значений атрибутов. Вторая нормальная форма требует, чтобы отношение было в 1НФ и каждый неключевой атрибут полностью зависел от всего составного ключа. Третья нормальная форма требует, чтобы отношение было во 2НФ и не содержало транзитивных зависимостей неключевых атрибутов от ключа.
