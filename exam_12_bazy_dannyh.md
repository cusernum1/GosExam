## 1. Реляционная алгебра

Реляционная алгебра - формальная система операций над отношениями.

Отношение можно понимать как таблицу, кортеж - как строку, атрибут - как столбец.

Операции реляционной алгебры возвращают отношения, поэтому их можно комбинировать.

---

## 2. Выборка

Выборка отбирает кортежи, удовлетворяющие условию.

```text
sigma_condition(R)
```

Смысл:

```text
оставить только строки, где условие истинно
```

SQL-аналог:

```sql
SELECT *
FROM R
WHERE condition;
```

---

## 3. Проекция

Проекция выбирает указанные атрибуты.

```text
pi_attributes(R)
```

SQL-аналог:

```sql
SELECT DISTINCT column1, column2
FROM R;
```

В классической реляционной алгебре дубликаты удаляются.

---

## 4. Переименование атрибутов

Переименование используется для изменения имен отношений или атрибутов.

SQL:

```sql
SELECT old_name AS new_name
FROM TableName AS t;
```

Оно особенно важно при самосоединениях и устранении неоднозначности имен.

---

## 5. Объединение, пересечение, разность

Объединение:

```text
R union S
```

возвращает строки, принадлежащие `R` или `S`.

Пересечение:

```text
R intersect S
```

возвращает строки, принадлежащие одновременно `R` и `S`.

Разность:

```text
R minus S
```

возвращает строки из `R`, которых нет в `S`.

Условие применимости: отношения должны быть совместимы по объединению, то есть иметь одинаковое число атрибутов и совместимые домены.

SQL:

```sql
SELECT * FROM R
UNION
SELECT * FROM S;

SELECT * FROM R
INTERSECT
SELECT * FROM S;

SELECT * FROM R
EXCEPT
SELECT * FROM S;
```

## 6. Декартово произведение и естественное соединение

Декартово произведение соединяет каждый кортеж первого отношения с каждым кортежем второго.

```text
R times S
```

SQL:

```sql
SELECT *
FROM R
CROSS JOIN S;
```

Естественное соединение объединяет отношения по одноименным атрибутам.

```text
R natural join S
```

SQL:

```sql
SELECT *
FROM R
NATURAL JOIN S;
```

На практике часто используют явное соединение:

```sql
SELECT *
FROM Orders
JOIN Customers ON Orders.customer_id = Customers.id;
```

## 7. Свойства операций

| Операция | Свойства |
|---|---|
| Выборка | сохраняет атрибуты, уменьшает число строк |
| Проекция | уменьшает число атрибутов, может удалить дубликаты |
| Объединение | коммутативно, ассоциативно |
| Пересечение | коммутативно, ассоциативно |
| Разность | некоммутативна |
| Декартово произведение | число строк перемножается |
| Соединение | выражается через произведение и выборку |

Соединение через декартово произведение:

```text
R join_condition S = sigma_condition(R times S)
```

## 8. Целостность реляционных баз данных

Целостность данных - согласованность, корректность и непротиворечивость данных.

Целостность по состоянию означает, что каждое допустимое состояние базы удовлетворяет ограничениям.

Уровни ограничений:

| Уровень | Пример |
|---|---|
| Атрибут | тип, `NOT NULL`, `CHECK` |
| Кортеж | условие между полями одной строки |
| Отношение | первичный ключ, уникальность |
| База данных | внешний ключ между таблицами |

---

## 9. Ссылочная целостность

Ссылочная целостность требует, чтобы внешний ключ ссылался на существующую строку родительской таблицы или был `NULL`, если это разрешено.

Пример:

```sql
CREATE TABLE Orders (
    id INT PRIMARY KEY,
    customer_id INT,
    FOREIGN KEY (customer_id) REFERENCES Customers(id)
);
```

Правила поддержания:

| Правило | Смысл |
|---|---|
| `RESTRICT` | запретить удаление или изменение родителя |
| `NO ACTION` | проверка ограничения без автоматического действия |
| `CASCADE` | изменить или удалить зависимые строки |
| `SET NULL` | установить внешний ключ в `NULL` |
| `SET DEFAULT` | установить значение по умолчанию |

## 10. SQL и операции реляционной алгебры

SQL - декларативный язык работы с реляционными базами данных.

Основные группы операторов:

| Группа | Назначение |
|---|---|
| DDL | создание и изменение схемы |
| DML | изменение данных |
| DQL | выборка данных |
| DCL | права доступа |
| TCL | транзакции |

Соответствие операций:

| Реляционная алгебра | SQL |
|---|---|
| Выборка | `WHERE` |
| Проекция | список столбцов в `SELECT` |
| Переименование | `AS` |
| Объединение | `UNION` |
| Пересечение | `INTERSECT` |
| Разность | `EXCEPT` |
| Декартово произведение | `CROSS JOIN` |
| Соединение | `JOIN ON` |

## 11. Нормальные формы

Нормализация - процесс организации отношений для уменьшения избыточности и устранения аномалий.

Аномалии:

- вставки;
- обновления;
- удаления.

Функциональная зависимость:

```text
X -> Y
```

означает, что значения `X` однозначно определяют значения `Y`.

---

## 12. Первая нормальная форма

Отношение находится в 1НФ, если все значения атрибутов атомарны.

Нельзя хранить список значений в одной ячейке.

Нарушение:

| id | phones |
|---|---|
| 1 | `111, 222` |

Исправление:

| id | phone |
|---|---|
| 1 | `111` |
| 1 | `222` |

---

## 13. Вторая нормальная форма

Отношение находится во 2НФ, если:

1. оно находится в 1НФ;
2. каждый неключевой атрибут полностью зависит от всего составного ключа.

Нарушение:

```text
(student_id, course_id) -> grade
student_id -> student_name
```

`student_name` зависит только от части ключа, значит 2НФ нарушена.

---

## 14. Третья нормальная форма

Отношение находится в 3НФ, если:

1. оно находится во 2НФ;
2. нет транзитивных зависимостей неключевых атрибутов от ключа.

Нарушение:

```text
student_id -> group_id
group_id -> group_name
```

Значит:

```text
student_id -> group_name
```

Это транзитивная зависимость.
